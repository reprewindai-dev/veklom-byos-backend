## 2024-05-18 - Avoid O(N) memory footprints via vector loads in DB lookups
**Learning:** Selecting the entire row using `.scalars().all()` on tables containing pgvector embeddings (e.g. 1536-dimensional vectors) causes severe Python memory and parsing bottlenecks, even when only scalar metadata properties are returned to the client.
**Action:** When implementing semantic search or vector retrieval methods, always select specifically the non-vector columns required (e.g. via tuple mapping `result.all()`) unless the vector itself must be forwarded downstream. Calculate cosine distances on the DB side and alias them to extract distance without loading the full vector to Python memory.
